# DATASHEET — BBO Capstone Query Dataset

**Author:** Gian Franco Cattaneo · Imperial Business School (Executive Master ML/AI)
**Scope:** Round 1 → Round 13 (terminal). **Last updated:** 2026-06-29

This datasheet documents the dataset accumulated by interacting with the black-box
optimisation portal. It follows the spirit of *Datasheets for Datasets* (Gebru et al.).

---

## 1. Motivation

The dataset exists to drive sequential Bayesian optimisation of eight unknown scalar
functions. It was generated by the author through portal queries; there is no external
collection. Each record is a (query, realised output) pair for one function in one round.

## 2. Composition

- **Units:** one record = one function evaluation. 8 functions × up to 13 rounds.
- **Functions and dimensionality:** f1 (2D), f2 (2D), f3 (3D), f4 (4D), f5 (4D),
  f6 (5D), f7 (6D), f8 (8D).
- **Input domain:** unit hypercube per dimension, **clipped to `[0.0, 0.999999]`**. The
  upper clip is a hard portal constraint — values of exactly `1.0` are not accepted; the
  bound is encoded as `0.999999` throughout.
- **Output:** single `float64` per query. Sign and magnitude vary widely by function
  (e.g. f1 ≈ 1e-270 … 1e-7; f5 ≈ 10² … 4.4e3; f8 ≈ 9.86).
- **Objective:** maximisation for all functions. Minimisation cases are negated upstream
  (correction applied R4→5).

### Schema

Two parallel newline-delimited files, one row per round, each row an 8-element list:

- `inputs.txt` — row *r* = `[array(x⃗_{r,1}), …, array(x⃗_{r,8})]`, each `x⃗` the query
  vector for that function (length = function dimensionality). 8-D arrays may wrap across
  physical lines; the parser re-joins continuations (`,\n␣␣` → `, `).
- `outputs.txt` — row *r* = `[y_{r,1}, …, y_{r,8}]`, the realised scalar outputs.
  Values are emitted as `np.float64(...)`; the parser strips the wrapper before `eval`.

Round *r* of `inputs.txt` aligns positionally with row *r* of `outputs.txt`.

## 4. Collection process

Records were produced one round at a time. Each round's queries were chosen by the GP-EI
pipeline plus override doctrine (see `MODEL_CARD.md` / `TECHNICAL_FOUNDATIONS.md`), then
submitted to the portal; the portal's returned outputs were ingested into the next round's
training set. **Portal feedback values are supplied fresh each round and are not persisted
outside the round files.**

## 5. Preprocessing

- Inputs: `StandardScaler` (zero-mean, unit-variance) before kernel evaluation.
- Targets: standardised per function for GP numerical stability; un-standardised for
  reporting.
- No outlier removal, imputation, or augmentation — every realised query is retained.

## 6. Coverage and gaps

- **Round 13 realised outputs are NOT included** in this repository for f1–f7: the terminal
  queries were submitted, but the portal returns were not ingested before termination. f8 is
  deterministic, so its Round-13 value is known a priori: **9.8596846**.
- Sampling is heavily concentrated near each function's incumbent optimum by late rounds
  (intentional exploitation), so the dataset is **not** a uniform design and should not be
  used to fit a global surrogate without re-weighting.

## 7. Uses and limitations

Intended use: reproducing the Round-1→13 optimisation trajectory and the final decision
logic. Not suitable for: global function reconstruction, transfer to other portals, or any
claim about the functions' closed forms (which remain unknown by construction).

## 8. Distribution & maintenance

Public GitHub repository (owner: `gianfranco365`), managed via the GitHub web interface.
The dataset is frozen at termination; no further rounds will be appended.
